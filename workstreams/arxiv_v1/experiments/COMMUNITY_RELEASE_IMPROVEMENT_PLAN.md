# ChemWorld 社区发布改良清单

日期：2026-10-09。目标读者：**研究者与 Agent 开发者优先**。用户已要求评估必要性、划分 Ours / LYJ 并建立 TODO。本页保存探索依据和逐项复核，**唯一认领/完成状态在 [FIRST_PAPER_TODOLIST 第 9 节](../FIRST_PAPER_TODOLIST.md#community-release-todo)**。本轮只完成评估与规划，不代表已实施 44 项改良、不改变冻结证据，也不授权正式软件发布。

## 判断与范围

ChemWorld 已经具备有价值的研究底座：公开动作合同、状态相关合法动作、原子事务、资源记录、合成仪器、终检、精确回放，以及多种过程模块。当前最需要的工作是让这些语义在不同操作粒度、失败结果、交互入口和发行方式下保持一致，并让新用户能独立完成研究循环。

建议首发定位为“有界、可扩展、可复现的虚拟实验环境”。不必在首发前实现任意化学体系或完整实验室。复核后为 **17 项必做、10 项合并交付、9 项条件触发、8 项发布后扩展**。合并项仍需交付其最小结果，但不各自新建系统；条件项和后置项不作为默认首发欠账。下文 P0/P1/P2 保留探索时的初排，实际排期与实施范围以本次复核和 TODO 为准。

必须区分三个对象：

- **本次实测的开发工作树**：本地 main，包版本 0.2.0；本报告的运行时缺陷默认只指这个对象。
- **公开仓库当前 main**：读取时包版本 0.4.0，已有 packaged Student Lab、CI、文档/发布 workflow、CITATION；本次只读检查其源码和元数据，没有执行其完整运行时。
- **冻结证据与 tags**：开发 README 指向 v0.2.0 冻结快照；公开可见 tags 为 v0.2.0/v0.3.0。现有冻结证据不因本次开发缺陷自动失效；main 的新增功能也不自动取得相同资格。

证据标记：**实测**为本次实际运行；**源码**为静态检查支持；**建议**为拟新增能力；**未验**表示尚无验证。P0 是相关发布范围内应先解决或明确移出承诺的事项；P1 是研究者首发的重点；P2 是后续能力扩展。表内验收条件均为建议，未声称已通过。

## 2026-10-09 必要性复核与两组分工

**不是每项都必须独立完成。** 默认最小发布范围为可安装的核心 Python/CLI、离线 Agent、公开合同、可读结果与精确回放。稳定 Gym/RL、Web UI、legacy 新实验、真实模型压缩恢复和正式排行榜必须逐项明确是否承诺；不能静默撤掉已有公开承诺来规避已知缺陷。

- **必做**：本次目标直接需要，完成限定范围即可，不默认实现原表列出的所有扩展形态。
- **合并**：并入已有工作交付并验证；不是取消，但不重复造 workspace、结果表、capabilities 框架或治理流程。
- **条件**：由实际发行范围或测量结果触发；未触发记 DEFERRED，不算必做未完成量。写入型 UI 即使标实验性，也必须满足 R05/R43 的基础边界。
- **后置**：有价值的新物理/科研能力，首发只需说明限制，当前不认领实现。

## 推荐推进顺序（按复核后的最小范围）

1. **先统一发行入口，保住当前证据。** 明确要从公开主线还是开发主线产生下一包，复用公开版已做好的 Lab、CI、CITATION；确认 CI 失败原因；修复发行文件范围和 Task Lab 写入边界。涉及 R05–R08、R13、R38、R41–R42。
2. **修研究语义。** 顺序建议为热控制、测量时钟、采样账、负结果结案，再处理风险/罚分和 Gym 适配。每项保留旧失败，更新合同及相应定向测试；受影响正式资格块从第一单元重跑，不为无关修改刷新旧证据。涉及 R01–R04、R09、R30–R35。
3. **跑通研究者完整旅程。** 安装→自定义 Agent→多批设计→笔记/证据→新进程恢复→分享/回放。修示例、CLI、历史分页和文档；给初次贡献者一个小扩展示例。涉及 R10–R22、R37–R40、R43–R44。
4. **稳定后做一次发行验收。** 用承诺支持的 OS/Python、干净 wheel/sdist、文档示例、核心过程路径、错误/负结果路径和公开边界形成一个可读结果。真实 UI 或某平台未验证就缩小支持声明；最终执行面稳定并获用户授权后，才进入 release-freeze。
5. **发布后扩展自由度。** 优先样品/容器身份，再混合物、组件实例和连续控制。这些是后续机制能力，不与本轮质量修复捆绑。涉及 R23–R29、R36。

上述阶段没有强行指定工期。Ours 的核心修复与 LYJ 的发行/应用/文档基础工作可以同时开始，最终示例和集成验收再消费稳定合同；不是先完成全部发行工作才开始修核心。每一阶段只执行复核表中的必做最小范围及已触发条件，合并项复用交付，8 项后置扩展不进入首发分母。

## 明确保留的优点与未知

不要为改良丢掉现有的精确回放、失败留存、事务原子性、可读资源账、公开/私有信息边界、缺失值 mask、模型卡或脚本恢复能力。三个八批研究还证明环境能支持“设计—观测—建模—前瞻预测”的小型循环；这些比单纯增加任务数量更有价值。

本次没有执行全仓测试、全新依赖安装、跨平台矩阵、真实浏览器、负载/长时规模基准、真实 provider 或压缩后的 LLM 研究恢复；没有独立重验远端当前 runtime。公开 CI 失败原因仍未确立，Gym wrapped info 失败也尚待定位。这些未知已转成具体验收项，不能写成已通过，也不妨碍本次有范围的改良清单完成。

报告与研究文档可以持续自主撰写：保存可检验的假设、实验设计、观察、分析、结论及未解决问题，引用原始数据。每个数据块执行前写一份简短说明，恢复时主动读取研究日志；持久文件的存在本身不保证模型会自动记住或正确理解它。
