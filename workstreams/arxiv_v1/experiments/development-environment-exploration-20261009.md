# 开发态环境探索 — 2026-10-09

问题：自主研究者使用当前 ChemWorld 公开 API 时，哪些科学操作可行，哪些受任务策略限制，哪些尚无运行时表达？本块为用户请求的开发探索，不产生论文或正式资格证据。

覆盖固定为 32 个单元：15 个注册任务的公开入口盘点；6 个 serious task 的公开 recipe 中点路径各一次；7 条边界路径（材料混合、样品/容器、过程控制、仪器配置、默认结晶、v5 自由结晶、开放电化学）；4 个构造请求（已支持反应世界、蒸馏加结晶、连续流加电化学、重复反应组件）。均使用 public-dev/任务默认分布、seed=0，不读取私有世界状态来选择动作。

边界路径检验意图固定：更换已投溶剂/催化剂及指定额外试剂身份；分样、指定接收器、对同一离线样品测量；压力/气氛/连续加料/中途测量控制；NMR/IR/MS 与 UV-vis 参数；结晶测量前置条件、无晶种冷却、过滤后再加工和提前终止；开放电化学的初始测量及单阶段关闭。每条最多 30 次提交；默认预算不够时停止，不追补有利结果。非法 schema 只校验不提交；可编码的拒绝动作保留实际回执。只允许预先写入脚本的条件分支（按公开 valid 状态执行可行路径和关闭），不依结果更换测试单元。

测量：公开 schema/可用动作、每次 validate 结果、实际事务及拒绝原因、观测与仪器信号、资源/时间/样品消耗、终止状态、精确 replay、构造兼容诊断。保留所有异常和未完成路径。单位结论使用 supported / rejected / partial / error；拒绝不等于平台故障。完整路径成功要求合法动作提交且完成 final assay；回放单独记录。中点路径不代表优化成绩。

停止规则：32 单元均有结果或记录异常即停止；不修复平台、不扩 seed、不重跑失败。单个操作超 60 秒报告 liveness；全块上限 15 分钟执行时间。脚本先完整落盘再执行；长任务逐单元打印 completed/total、吞吐和 ETA。

预期输出：仓库外唯一目录中的 exploration.py、summary.json、各路径 append-only 诊断 JSONL 与原生轨迹 JSONL；总结在本说明追加，给用户中文解释与改进优先级。既有生成证据不作为本块输入，故无需刷新 current 绑定或历史审计。

## 实际受限的研究意图

1. **同一批材料分样做对照，再独立操作或合并。** `split_sample` 未注册；`transfer` 无 `target_vessel`，
   `sample` 和 `measure` 无 `sample_id`。这限制的是公开接口中的可操作样品身份，不能据此说内部完全没有
   vessel/phase/sample ledger。实测先 sample 1 mL，再 HPLC 会从当前批额外消耗 0.2 mL，不能指向先前那份样品。
   希望支持有身份、位置、组成、储存历史和谱系的 aliquot，以及 split/merge/route。
2. **混合溶剂、双催化剂或另选试剂做机制干预。** 已加入 solvent=0 后再加 solvent=1，返回
   `payload_locked:solvent`；第二催化剂同样返回 `payload_locked:catalyst`。`add_reagent` 增加 species_id
   被 `payload_fields_declared` 拒绝。希望允许显式组成及可反应物种，在已声明模型适用域内做 mixture 干预。
3. **把已支持过程串成新的实验装置。** 反应+热+蒸馏+结晶+观测因 phase_transition 所有权冲突和
   unsupported_combination 被拒；连续流+电化学组合也被拒；重复 reaction 组件被直接拒绝。
   目前构造器按 8 种注册组件集合匹配，尚不是可自由实例化设备、连边和回流的过程图。
   希望组件拥有实例级状态，通过显式物料端口连接，先打通蒸馏接结晶、双釜对照等小图。
4. **过滤后复溶、重结晶或对产品继续加工。** 默认与 v5 两条路径中，filter_crystals 后 heat 和 add_solvent
   均被 `isolated_crystals_require_assay_or_termination` 拒绝。过滤前的浆料可继续干预，不应误报成整个
   结晶过程不可逆。希望分离产品仍是可转移和加工的普通材料对象。
5. **在过程进行时根据新证据调整控制。** pressure_Pa、atmosphere、measure_every_s、ramp_K_s 均不属于
   heat 的公开字段；feed_reagent 未注册。可以分段 heat/wait/measure，但没有长动作内部的采样触发、
   中断或并行反馈接口。希望用事件/时间调度器表达温度程序、加料和异步测量。独立 cool 未注册，
   但把 heat 的目标温度调低实际可以降温；这部分是命名/文档障碍，不能声称无法冷却。
6. **为一个假设设计测量，而不只挑固定仪器名。** 公开 measure 不接受 wavelength_nm 和 integration_time_s；
   nmr/ir/ms 都在编码阶段返回 Unsupported instrument。当前读到的底层光谱工具不等于可调用仪器。
   希望开放测量方法、校准/空白样、积分时间和检测限的代价权衡，再接入真正可调用的补充仪器。

## 需要单独说明的策略边界和实现问题

- **已有自由度必须保留在结论中。** v5 实测允许不做前置 HPLC 而加晶种、过滤；开放电化学实测允许初始
  pH 测量和单阶段电解后终检。默认任务的严格测量顺序不能概括为底层永久限制。结晶 v5 仍要求分离晶体
  才允许正常 terminate，弃批与正常终检应分别理解。
- **测量时延与运行时钟未接通。** 仪器合同声明 UV-vis 90 s、HPLC 600 s、final assay 1200 s；本轮
  32 次已提交测量（含这些仪器）全部 delta_time_s=0。源码 `runtime/instrument_cost_services.py` 只给
  particle_size 增加 120 s。尚不能表达“等待分析结果时反应继续/样品老化”的实验权衡；时延元数据不等于
  已执行时序。建议先明确仪器时钟与反应器时钟，再实现异步结果回传，避免简单增加时间而不推进过程。
- **操作惩罚与物理风险共用读出。** 第二溶剂请求被拒，物理体积/温度/时间不变，但公开 delta_risk 增加
  0.08。其他预条件回滚也增加 0.08；源码明确将此作为 rollback penalty。它是现有评分设计，不是物理
  状态已发生危险变化的证据。希望把无效操作惩罚与物理风险分别记录，便于研究风险敏感决策。
- **取样回执容易误读。** sample 1 mL 后体积和累计消耗逻辑确实减少，但回执顶层 sample_consumed=0，
  因 record_services 只在 measure 分支填写该字段。应明确它是“仪器消耗”或统一为所有取样操作的消耗。
- **文档有可用性漂移。** operations 文档列有 cool/stir，当前操作词表未注册这两个独立动作；limitations
  文档谈及 NMR/IR/MS 合成观测，但当前公开 measure 不支持这些仪器。建议文档从公开注册表生成并说明层级。

## 建议顺序与结论边界

优先 P0：有身份的多样品/多容器操作，以及分离产品可继续加工；这是实际执行对照实验和连续研究链的基础。
优先 P1：统一过程/测量时序、拆开风险和接口惩罚、澄清取样回执；同时使自由研究模式与任务打分流程明确分离。
优先 P2：基于端口的过程图、混合物和可配置仪器；每次扩大一个有明确模型域的小范围能力。

以上是当前 checkout 公开接口的单 seed 开发探索。未比较不同方法、未验证普遍机理识别能力或真实化学效度，
也没有把预期的非法操作拒绝计成平台崩溃。可追溯、资源记录、校验和回放在本轮路径上工作正常；研究自由度
主要受对象身份、可组合拓扑、生命周期与控制/测量表达能力约束。
