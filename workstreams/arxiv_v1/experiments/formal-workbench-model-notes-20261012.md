# R63：自主模型实验与版本笔记的限定正式验收

## 执行前固定设计

用户于 2026-10-12 明确要求正式实验并包含模型笔记。本块是当前工作台数据路径的三案例正式验收，不是论文历史证据复现、多模型排名或笔记效果的因果实验。不改原论文与 Work II。

固定顺序：reaction-to-assay、reaction-to-crystallization、flow-reaction-optimization，各一个独立模型会话、一个物理批次，seed 7、操作预算 24。模型沿用既有已登录原生入口 gpt-5.6-sol / medium，无 shell、联网检索或子 Agent。只提供公共任务、状态、schema、历史、测量与笔记工具，不提供参考配方、旧实验结果或隐藏状态。三组各自的科学问题为反应产率/选择性、结晶回收/纯度、流动转化/选择性；具体条件和测量由模型决定。

明确要求模型在物理实验前写简短可检验预期，在重要证据后修订，在终检后写结论、证据和局限并提交报告。笔记格式自选、正文按需读取，不强制逐步理由或读取次数，不请求内部思维。漏写不锁定实验，也不由宿主补写。终检关闭物理环境后仍允许模型读取已保存证据和写报告。

每组最多 40 次工具请求（错误及笔记读写同计）、420 s；块最多 1260 s，组间累计 input+output tokens 达到 1500000 后不启动下一组。原生单会话完整 token 用量只在会话结束可得，该数是组间停止阈值而非实时硬上限。缓存 tokens 已含在 input 中，不重复相加；订阅费用不可归因则 USD 记 null。每 20 s 输出组/3、工具/40、操作/24、耗时、吞吐和可用 ETA。

执行前完成工具宿主定向测试并提交稳定代码；source commit、锁定环境及执行文件摘要记录在仓库外的 source-binding.json，一次绑定，不重建全局 readiness 或旧审计。原生提供方由既有 adapter 校验登录，不读取或复制临时 API key。本块不验收网页 BYOK。

固定读出与判定：

- 三个槽位逐一报告已执行、未启动、终检、截断、拒绝、回滚、宿主/提供方失败；所有非空轨迹零容差精确回放。
- 工程通过：三组终检、精确回放、完整提供方用量、无宿主/传输/平台失败。模型合法动作拒绝单列保留，不自动视为平台缺陷。
- 笔记通过：每组存在操作前及终检后的模型版本和最终报告；人工核对原文、事件引用时点、已测/未测边界。读取次数只报告，不作为通过条件。笔记不自动成为事实。
- 保存资源状态、全工具 IO、原始公开测量、全部版本与报告；模型工具请求数与不可观测的底层模型请求数分开。没有终检的指标为缺测，不填零。

停止规则：不自动重试、不替换不利结果。提供方/传输失败停止该组；宿主异常、constitution 回滚或精确回放失败停止整个块，剩余槽位明确未启动。已有 R62 的 240 s 加热回滚仍是已知待定位限制；不刻意指定回避该条件，也不把旧结果喂给模型。若本块遇到平台缺陷，保留失败，修复后的正式验收必须另从三组第一组开始，不拼接结果。

输出：仓库外 `D:/Projects/ChemWorld-local-research/20261012-formal-workbench-model-notes/attempt-01/`，含 `store/` 工作台原生档案、各组 provider/tool IO、source-binding、机器 summary 和可读 review。仓库仅提交运行器、测试、本说明与不含原始提供方正文的派生汇总。

## 模型笔记的实际价值与错误

三组均在事件 0 写下初始笔记；两组已终检实验均有终检后笔记，失败组有回滚后的记录与最终失败总结。12 个版本中的显式 `event-NNNN` 引用全部已在写入时存在，未来/不存在引用为 0。三组 notebook_read 均为 0：这里验证了可供人审查的同期科学表达，**没有验证主动回读、跨上下文恢复或能力提升**。自动 `notebook_passed` 字段只对应预定前/终检后/报告的结构覆盖；流动组因没有终检而为 false，并非没有写笔记。存在版本也不保证科学表述正确。

- 反应组在 HPLC 后保留了“高转化、低选择性，因此不再延长加热”的同期决定，后续 quench/terminate 与之相符。数值可核对，但没有对照或重复，不能定位机制或最佳条件。
- 结晶组保留了细粉读数为 1.000 的负面结果，并否定原先的抑制细粉预期。该值是有噪声、有边界的代理读数，不能视为精确测得所有实体晶体均为细粉。高纯度的一条轨迹不能隔离晶种、慢冷各自的因果贡献。
- 结晶 v3/v4 说前置拒绝“产生程序惩罚”，与工作台路径不符：验证器返回潜在 cost_penalty=0.1，但动作没有派发给核心，最终 cost_components.precondition_failure=0。原文保留，不由审查者改写。v4 还把实际 0.015 g 晶种写成行动前预期，而 v1 原计划约 0.02 g；版本对照能发现这类事后归整。
- 流动组把输入的 residence_time_s=300/900/1800 当成实际停留时间。当前固定 18 mL 硬件按流率推导的值分别是 1080/4320/10800 s，输入字段只保存为 requested 值。因此笔记中的条件表述不准确。温度与流量同时改变，也不能独立归因“高温加速副反应”；它只保留了两条已运行条件下不同的 HPLC 观测。最后一组没有 final_assay，不能将 HPLC 指标当终检成绩。
- 流动 v4 曾提出恢复策略，并额外提交了一次 set_flow_rate；宿主按原停止规则拦截。v5 和终报告承认未完成，不补造终态。这说明返回失败时应直接展示“物理执行已停止”，避免只留笼统错误让模型误判还可继续。

这些笔记是模型公开提交的可错陈述，不是内部思维，也不是已验证事实。原文和全部旧版本保留在仓库外，网页只读呈现；本页是另外的人工审查层。

## 失败定位与待修复限制

结晶两次前置拒绝分别是 `seed_crystals_requires_current_reaction_assay` 和 `filter_crystals_requires_current_slurry_assay`，模型自行补测后继续。流动三次前置拒绝均为状态相关 duration_s 下界，最新 schema 分别要求至少 1080、4320、10800 s。

流动 event-0014 的回滚事件保留了 `vessel_temperature_bound`，但**不能解释成实测过热**。静态核对当前执行源码可定位合同不一致：`set_flow_rate` 用固定容积与 0.1 mL/min 推导 10800 s；公开 run_flow schema 接受 duration_s=10800（区间 10800–14400），而 `_run_flow` 对配置停留时间检查上限 7200 s。异常捕获随后人为构造“容器最高温度 + 1 K”的候选状态来触发事务回滚，原始异常类型/原因没有直接呈现给模型。此前 R62 的加热回滚也用了相同温度检查项，但热服务同样有异常转温度的包装，不能据相同检查项断言两个底层原因相同。

另发现本轮原生宿主的 lab_schema 在创建时缓存 schema；模型仍可从 lab_status 取得最新 available_actions/schema，但之后再次调用 lab_schema 不会更新动态边界。这是后续修复点，本次数据仍绑定原执行源，不事后改提示或替换结果。

后续必要工作已在 R64 登记：统一流动配置与运行域、明确 requested/实际生效参数、保留原始领域错误并直接返回停止状态、动态读取 schema。先修复和定向验证；若重新做正式验收，必须另启完整三组，原失败保持独立。**本轮未修改核心、未重跑、不把开发修复自动升级成通过资格。**
