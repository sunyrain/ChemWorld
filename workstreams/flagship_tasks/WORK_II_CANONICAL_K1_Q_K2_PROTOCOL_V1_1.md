# Work II 通用 K1–Q–K2 封存后测协议 v1.1

状态：**冻结，前瞻适用**

冻结日期：2026-09-19

任务编号：W2-129

性质：设计与提示合同；本文件本身不产生实验数据

替代关系：本版本在首个前瞻数据块使用前替代 v1.0。唯一的提示语义变化是把所有自由文本输出统一为英文；封存顺序、科学问题和评价边界不变。v1.0 继续保留为历史版本，不覆盖或删除。

## 1. 目的、语言与适用范围

本协议把来源实验结束后的三类产物分开封存：

- K1：完整、独立可读的机理报告；
- Q：对十二个预注册新批次的盲预测；
- K2：在没有收到预测真值时进行的七项反思性复盘。

K1、K2 的 `report`，Q 的逐题和总体 `rationale`，以及本后测链要求的其他自由文本字段必须使用英文。JSON 键名、批次号、变量名、单位和公式保持其规范写法；不能用非英文长段落绕过语言要求。数值不受语言规则影响。

本协议适用于能够形成机理报告、定义任务相关预测指标，并在来源结束时封存任务交付的 ChemWorld 任务、世界、先验层、资料臂和研究目标。任务的物理操作、指标和查询内容仍须逐块预注册；不得因为本协议通用，就把不同体系强行改成相同化学任务或相同六指标。

本协议只约束冻结以后开始的新数据块。既有 EC、RX 和其他历史结果继续按实际使用的提示、工具预算和失败记录解释；不得用本协议追溯改写、翻译、补齐或重新命名旧产物。以后若要修改本协议，必须新建版本并在数据块开始前声明，不得静默覆盖 v1.1。

## 2. 规范性封存顺序

每个独立来源会话使用以下顺序：

1. 完成来源实验，封存原始轨迹、观测和任务交付；适用时同时封存操作建议。
2. 提交 K1；K1 一经接收立即封存。
3. 才向同一会话公开整组 Q；提交 Q 后立即封存。
4. 在不反馈任何预测真值、评分或隐藏机理的条件下提交 K2；K2 另存，不能覆盖 K1 或 Q。
5. 只有 K2 封存后，评价器才可生成或读取真值、评分、复测结果和外部评审。

K1、Q、K2 阶段不得补做物理实验，不得访问实验室取得新证据。后测只可使用来源阶段已经进入该会话的资料、观测、研究记录和本块预先声明的公共计算能力。

## 3. K1：逐字固定的默认提示

对于来源阶段存在操作建议的任务，下面内容逐字使用，不增删问题，不附带候选机制，不规定模型形式或字数上限：

```text
实验阶段已结束，操作建议已经封存。现在请用英文提交完整、独立可读的机理报告。
请讲清你认为这个世界如何运行：关键变量、作用关系、耦合、可能的方程或过程；哪些实验使你形成或修改这个解释；说明解释适用范围、尚不能识别的因素和合理的竞争解释。
使用你认为最合适的自然语言、数学或伪代码，不要求任何预设模型形式，也不要求确定答案。
引用真实批次编号与数值，区分实际观测、外推和猜测；不补做实验，不编造未测信息。
**请充分展开，不必压成短摘要。所有报告文本必须使用英文。**返回JSON的report字段。此报告封存后才给预测题。
```

规范输出：

```json
{"report": "Complete mechanistic report in English"}
```

若任务按定义没有合法的操作建议，必须在该数据块开始前声明其任务交付类型，并且只允许把第一句中的“操作建议”替换为“任务交付”；其余内容保持不变。不得在看到来源结果后决定是否使用替代句。

## 4. Q：固定外层提示与任务预注册载荷

下面外层提示逐字固定：

```text
请基于你自己的研究，对以下12个独立新批次的最终结果逐一盲预测。每批从相同初始世界独立开始。对每个指标给出点估计及80%预测区间，考虑不确定性；不能补做实验。所有指标沿公共仪器及评分合同。题目并未限定你解释机理的形式。不要修改先前报告。返回完整predictions及rationale；所有rationale和其他自由文本字段必须使用英文。
```

紧随其后一次性附加本块冻结的查询 JSON。任务块必须在任何来源实验开始前固定：

- 十二个查询的 ID、顺序和完整动作序列；
- 每题需要预测的任务相关指标、单位和允许范围；
- 生成参考真值、噪声实现、评分、缺失值和越界值的规则；
- 同一世界内 Opaque、Aligned、MisIndexed 及配对研究目标是否共用完全相同的查询；默认共用；
- 查询与来源已做条件是否允许重合；预注册重合可以存在，不能把“新批次”擅自解释成“所有条件从未做过”；
- 查询集的文件路径、内容摘要或其他不可歧义标识。

查询不得依据某个来源实际选择的实验、得分、K1 内容或失败状态事后挑选或更换。默认恰为十二题；若特定任务不适用，须通过新协议版本或数据块开始前的显式偏离说明处理，不能在运行中临时减题。

每个数值指标至少使用以下结构；`lower80 <= estimate <= upper80`，三者单位一致：

```json
{
  "predictions": [
    {
      "query_id": "Q01",
      "metrics": {
        "metric_name": {
          "estimate": 0.0,
          "lower80": 0.0,
          "upper80": 0.0
        }
      },
      "rationale": "Concise English rationale and principal uncertainty for this query"
    }
  ],
  "rationale": "Optional overall calibration statement in English"
}
```

字段名可按既有解析器作无语义变化的映射，但点估计、80%区间、逐题英文依据和完整十二题不得省略。方向、排序或类别任务应在块说明中预注册等价的紧凑结构和评分规则，不得伪造不适用的连续数值。

## 5. K2：逐字固定的七项复盘提示

下面内容逐字使用：

```text
机理报告和盲预测已经封存，尚未向你反馈任何预测真值。请用英文按1—7逐项深入复盘。
引用真实批次和K1中的具体判断；不得补做实验，不得修改已经封存的K1或Q。
请引用前文，避免重复完整实验表和整篇机理报告。允许承认不足，不要把事后解释写成实验当时已经形成的判断。

1. 初始资料中的哪些重要主张得到支持、受到反驳或仍未检验？如果初始资料没有提供实质性主张，请明确说明。区分“没有发现反证”与“已经出现反证但当时没有修正”。
2. 哪些具体实验真正形成或改变了你的判断？哪些关键实验选择主要依赖初始资料、已有数据或未经验证的猜测？
3. 当前最重要的竞争机理或竞争解释是什么？现有实验能够区分哪些、不能区分哪些？
4. 如果只允许增加一次合法的完整实验，你会选择什么条件、测量什么？不同可能结果分别会怎样改变你的判断？不要实际执行。
5. 你的实验设计在机理可辨识性与提高操作得分之间做了什么取舍？研究目标怎样影响了你的实验选择？是否存在为了优化而牺牲辨识性，或为了辨识而牺牲得分的情况？
6. 哪些已经取得的证据没有被充分利用或难以利用？哪些盲预测最不可靠，哪些预测区间可能过窄？指出它们是否与K1声明的不确定性或适用范围不一致。
7. 封存推荐操作有什么局限？如何检验其重复性、局部稳健性、跨材料或跨世界推广范围？区分“样本内最高”与“已经证明最优”。

返回JSON的report字段；report内容必须使用英文。
```

规范输出：

```json
{"report": "English retrospective answering items 1 through 7"}
```

若任务按预注册定义没有操作推荐，第 7 项只评价相应的封存任务交付及其推广边界，并明确“operation recommendation is not applicable”；不得为了回答问题而编造配方。上述七项问题是统一受评提示。EC 历史案例的“回答要点”只可作为评价人员理解案例的注释，不得发给受评 Agent，也不得当作标准答案。

## 6. 三类产物的解释边界

- K1 是来源结束时的机理主张与证据边界，不因后续回答更流畅而被 K2 覆盖。
- Q 是外部可评分的预测与区间校准产物；诚实写出未知不等于预测区间已经正确表达未知。
- K2 是统一提示诱发的反思性审计，可揭示遗漏、矛盾和下一步判别思路，但不是独立实验，也不证明 Agent 在来源阶段已经持有这些认识。
- K2 第 4 项提出的实验不得执行，也不得计为来源动作、发现成功或优化成功。
- K1、Q、K2 可以分别评分；不得把语言质量、机理正确性、预测精度、区间覆盖和推荐得分压成未经校准的单一总分。
- 英文输出要求只统一交付语言，不改变科学评分标准；不得把英语文风本身当作机理正确性的代理指标。

## 7. 公共计算能力与失败修复

每个数据块必须在开始前固定 K1、Q、K2 可用的工具和调用预算，并对同一比较块的所有臂使用相同政策。默认只允许无外部数据的公共计算器，不允许实验室、隐藏真值、仓库、网络或新的物理调用。对于含十二题、多指标和 80% 区间的 Q，默认计算器调用上限为 128；也可以整块禁用，但不能按某个来源表现临时改变。

来源、K1、Q、K2、推荐复测和评价器分别记录状态。解析错误、provider 中断、计算器额度不足、语言字段不合规或线程续接故障属于平台/后测状态，不自动等于科学失败；语言不合规按块说明决定解析失败或单列格式失败，不能人工翻译后冒充原回答。

若预注册规则允许修复后测失败，只能：

1. 保留原失败响应和状态；
2. 续接同一来源 thread；
3. 使用完全相同的已冻结提示和查询；
4. 不增加物理实验、不反馈真值、不修改 K1；
5. 只修复已确认的平台边界，并把原结果与修复结果分开报告。

不得因为回答语言不够流畅、回答质量低、预测误差大、区间覆盖差或推荐得分低而补跑或更换查询。

## 8. 每个数据块必须冻结的附录

运行 note 或配置至少列出：

| 字段 | 必须冻结的内容 |
| --- | --- |
| 研究单位 | 任务、世界、先验层、资料臂、研究目标、模型与推理档位 |
| 来源资源 | 完整实验数、额外测量、操作/时间/物料预算、失败与停止规则 |
| 任务交付 | 交付类型及是否存在操作建议；若不适用，声明 K1/K2 的唯一允许替代语义 |
| 输出语言 | K1/K2 report、Q rationale 及其他自由文本为英文；验证与失败处理 |
| Q 载荷 | 十二题 JSON、顺序、动作、指标、单位、范围及内容标识 |
| 比较配对 | 哪些臂和目标共享查询、世界、噪声或参考；推断单位与依赖关系 |
| 后测工具 | K1/Q/K2 的工具种类、调用上限、超限状态及允许的修复规则 |
| 真值与评分 | 参考生成时点、噪声、评分、区间覆盖、失败和缺失处理 |
| 输出与绑定 | 原始响应、规范化 JSON、状态、thread、来源/K1/Q/K2 不可歧义绑定 |

没有完成该附录的块不得声称遵循本协议。

## 9. 最小验收条件

一个会话只有在以下事实分别可核对时，才能标记相应阶段完成：

- 来源交付已封存，且 K1 提示中没有暴露具体 Q；
- K1 原文与解析结果都已保存，`report` 为英文；
- Q 在 K1 封存后一次性给出，十二题齐全，真值未回流，所有 `rationale` 为英文；
- K2 在 Q 封存后给出，七项齐全，`report` 为英文，且没有改写 K1/Q；
- 物理调用在来源结束后为零；
- 所有原始失败、修复与工具调用都有独立记录；
- 同一比较块的提示、查询和工具政策没有因观察结果而改变。

该验收只证明流程执行符合协议，不证明机理正确、预测准确、推荐最优或结论能够跨世界推广。
