# 晶种请求、实际执行与认识记述的区别

这是对保留轨迹的解释核对，不产生新实验。全部30场结晶机会会话已逐场精读：15场研究组的50版笔记、180批操作与结果，以及研究/无研究两组全部K1/Q/K2。下列操作计数覆盖全部15场研究组；认识判断以逐场引文和执行状态为依据，不由操作失败数量自动推定。

## 操作事实

冻结执行提交`d2b05e98`的`src/chemworld/world/operations.py`同时规定单次晶种上限0.05g和累计晶种上限0.05g。`src/chemworld/operation_validator.py`的`public_field_bounds`以该累计限额减去已经加入量，限制下一次合法加种。12g的研究总库存不是单批允许累计加入12g，也不能通过反复调用绕过0.05g的物理操作范围。

[机器逐批表](operation-semantics/seed-execution.json)覆盖180个实际研究批次：8/15场、28/180批包含被拒的加种请求，共516次。这只是操作请求和执行的差额，**不是8场发生认识错误的自动计数**。重复请求不是独立实验，也不是服务器中断。

|---|---|---|---|
| 第一重复W03 | 8–12 | 0.10–0.15g | 各0.05g |
| 第一重复W05 | 6–8、11–12 | 0.06–0.25g | 各0.05g |
| 第二重复W02 | 3、9 | 0.50g、0.20g | 各0.05g |

第二重复W02的原始公开资源状态提供了直接交叉核对：第31次操作成功加种后，全研究累计种库存消耗0.12g；第32至40次请求被拒后仍为0.12g。第114次成功加种后累计消耗0.42g；第115至117次请求被拒后仍不变。失败消息为`Action precondition failed: payload_bounds:seed_mass_g`。上述冻结代码、操作状态与资源状态相互一致。

## 已读记录中怎样产生了不同解释

**第一重复W03。** 终末笔记和K1/K2将0.10–0.15g写成已经完成的剂量，并把较低细粉部分归于增种。它同时承认冷却端点混杂、不能建立单调剂量律，但这些限定没有纠正“剂量确实改变过”的错误前提。局部材料比较和改变反应历史的收益仍真实存在。

**第一重复W05。** 版本2在实验前提出生长表面与粒子数负担两种候选；版本3要求在S1内检验剂量，后续确实尝试了多次加种。版本4及封存报告却把请求0.25g的失败与请求0.06g的成功组合成中间剂量最优的解释。两种实际剂量均为0.05g，不能支撑这条剂量结论。末两批的相同实际配方仍形成局部重复支持，不能因解释有误而删除操作成果。

**第二重复W02。** 存在一条真实的低温长时预期—执行失败—返回旧配方—公开撤回链；同一会话却把被拒的0.50g和0.20g加种写成做过的实验。认识的不同部分并不自动同步：能够准确修订反应预期，不代表准确记录了所有干预。

**第二重复W03。** 这里的时间依据更强。版本2已经把第三批写成1.0g，随后明确计划1.5g；版本3继续以所谓1.0/2.0g结果解释材料与过饱和度，版本4又安排更高投料配1.5g。实际每批仅0.05g被提交。错误经历记述因此不仅出现在终末报告，也进入了后续实验请求。与此同时，模型根据真实粒度观测撤回了S0再热路线，并找到有重复支持的低投料S1工艺。

**第三重复W01。** 版本3以“1g种量没有帮助”为由暂时搁置种晶路线；该批实际0.05g，19次追加请求遭拒。它同时提出并实际检验进一步稀释的预期，随后承认更低投料失去可回收晶体。一个因素上真实受反证约束，不保证另一个因素的证据前提准确。

**第三重复W03。** 在第11批后、末批前的版本2中，研究者把低投料与所谓1g种晶得到的低细粉视为质量线索，预期满投料配高种量可以保留质量。第12批细粉升至1，终末记录撤回该扩大方案，却仍把10g种晶写成实际经历。第11与12批均只加入0.05g；主投料、催化剂比例等同时改变。不能把这条真实的失败和修订链写成1g到10g的剂量检验。K2提出五次0.05g的方案也超过单批累计限额，且未执行。

**第三重复W04。** 确实存在不加种与加0.05g的比较，但后者被写成0.5g。Q明确借助“高剂量种晶经历”判断新增种量的细粉代价。因此不能把整条种晶比较说成没有实验，也不能保留其错误的剂量尺度。

**第三重复W05。** 第9与10批实际都加入0.05g；第10批第二次0.05g请求被拒。版本3、末笔记及封存报告把它记为“翻倍没有明确效果”，甚至把第9批描述为节约一半晶种。即使结论语气谨慎，其比较前提仍不成立。两批可支持局部工艺的近重复，不能支持剂量无效或节省一半资源。

相应的准确记录同样重要：第二重复W04明确识别累计0.05g上限，没有把研究总库存当作单批允许用量。其他没有超额请求的会话也不能自动判为理解了限额，只能说明未观察到该类请求/执行差额。

这些案例应区分三件事：研究者计划改变什么；世界实际接受了什么；研究者后来认为自己检验过什么。仅有一份操作请求列表或语言上承认“有混杂”，不足以确定证据支持范围。

## 对报告和论文的影响

本轮初稿曾在第一重复W03和W05沿用原生`batch.actions`中的请求剂量。现已核对逐事件状态并修正[逐场解读](READING.md)；原始笔记、请求、观测、失败及定量结果保持不变。提取脚本现在明确标注原生动作列表含被拒请求，另附每批请求/提交晶种量及失败位置，避免读者将请求视为已执行干预。

这不会改变既有预测误差和终检数，也不构成重跑表现不佳会话的理由。它改变的是科学解释：不能把这些记录当作高晶种剂量机制检验；可以研究其如何把未发生的操作纳入经验叙述。八场都找到了相应记述，但它们的时间依据、后续用途和同时存在的真实对照各不相同；不宜合成反绎成功率或普遍心理机制。作为主文证据时，应优先选择有中途笔记、实际后续行动和明确使用依据的过程，并与准确处理限额及真实修订的案例并列。

复算命令：`uv run --no-sync python -m scripts.analyze_unified_c_histories seed-report`。逐句引文及事件锚点在`reading.json`，以`verify`命令核对；机器核验只验证锚点和覆盖，不替代语义判断。
